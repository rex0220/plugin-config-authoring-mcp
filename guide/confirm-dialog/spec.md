# 確認ダイアログ: 設定ファイルの書き方

`cdlg_*` のツールが読み書きする設定ファイル（元の値）の形です。確認ダイアログプラグイン Ver.6 以降。設定画面の「設定をダウンロード」のファイルとは形が違います（`cdlg_new` の `from` で写す）。

```json
{
  "common": {},
  "rows": [
    {
      "key": "01", "state": true, "name": "高額の確認", "event": "save",
      "save": { "create": true, "update": true },
      "steps": [
        {
          "state": true, "desc": "100 万円以上", "cond": "金額>=1000000",
          "dialog": true, "icon": "warning",
          "title": "\"金額の確認\"",
          "body": "\"見積金額は \" & FVAL(金額) & \" です。<br>保存しますか？\"",
          "notify": true, "ok": "\"保存しました\"", "cancel": "\"金額を見直してください\""
        }
      ]
    },
    {
      "key": "02", "state": true, "name": "承認の確認", "event": "process",
      "actions": [{ "name": "承認", "from": "処理中", "to": "完了" }],
      "steps": [
        {
          "state": true, "desc": "承認", "cond": "1", "dialog": true, "icon": "question",
          "title": "\"実行確認\"",
          "body": "EV_INFO(\"action\") & \": \" & EV_INFO(\"status\") & \" -> \" & EV_INFO(\"nextStatus\") & \"<br>続行しますか？\"",
          "notify": true, "ok": "\"ID:\" & $id & \" を承認しました\"", "cancel": "\"承認をやめました\""
        }
      ]
    }
  ]
}
```

## レコード画面での動き（先に読む）

- **保存**（追加の画面・編集の画面・一覧での編集）: 「使う」の保存イベントの行を上から、行の中はステップを上から見て、**表示条件が真のステップを全部集め、順に 1 つずつダイアログを出す**。OK で次へ進み、最後まで OK なら保存される。途中でキャンセル（× や Esc も）すると、そこで止まって保存されない（画面にエラーの文が出る）。
- **アクション**: 実行したアクション（名前・元のステータス・先のステータス）を選んである「使う」のプロセスアクションの行について、同じように出す。キャンセルすると実行されない。
- **ボタン**: 「使う」のボタンクリックの行ごとに、詳細・追加・編集の画面にボタンを出す（表示条件が真のとき）。押すと、その行のステップを順に出す。レコードは保存しない（見せるだけ）。
- 出すダイアログが複数あるとき、最後以外の OK のボタンは「次へ」になる。
- 行の並び・ステップの並びが、出る順になる。
- 編集の画面の保存とアクションの実行の前に、レコードが他の利用者に更新されていないかを確かめる。更新されていれば知らせを出し、確認ダイアログは出さない。
- 表示言語は 日本語・英語・中国語（簡体字）を見分ける。ほかの表示言語は英語として扱う。

## 行（`rows[]`）— 1 行が 1 つの設定

| キー | 中身 |
| --- | --- |
| `key` | 行のキー（"01"…。位置で決まる。書かなくてよい） |
| `state` | この行の設定を使う。`false` の行は何もしない（設定は残る）。省くと `true` |
| `name` | ダイアログ名（設定を見分ける名前。レコード画面には出ない）。`state` が `true` なら必須 |
| `event` | 対象イベント。`"save"`（保存イベント）/ `"process"`（プロセスアクション）/ `"button"`（ボタンクリック） |
| `save` | `event` が `save` のとき。`{ "create": true, "update": true }`（追加 / 更新のどちらで出すか）。**省くと両方 `true`** |
| `actions` | `event` が `process` のとき。ダイアログを出すアクションの並び `[{ "name", "from", "to" }]` |
| `buttons` | `event` が `button` のとき。画面ごとのボタン `{ "detail": {…}, "create": {…}, "update": {…} }` |
| `steps` | ステップ（ダイアログと通知）の並び。必須（空の並びでもよいが、何も出ない） |

- 対象イベントで使わない群（`save` に対する `actions` など）は書かなくてよい。今の設定を写した設定ファイルに残っていることがある（設定画面が覚えている値。そのままでよい）。

### 保存イベント（`save`）

- `create` = 追加の画面の保存、`update` = 編集の画面の保存と、一覧での編集の保存。

### プロセスアクション（`actions`）

- `name` = アクション名、`from` = 実行する前のステータス、`to` = 実行した後のステータス。**どれもプロセス管理の既定の名称**（言語ごとの名前ではない）。`cdlg_fields` の `process.actions` のとおりに書く。
- アプリのプロセス管理に無いアクションは、検査が warning（`action.notFound`）で知らせる。取り込めるが、レコード画面では使われない。
- プロセス管理で名前を変えると、変える前の名前の設定は効かなくなる（名前で覚えている）。
- 同じアクションを 2 つ書いても、ステップが出るのは 1 回。

### ボタンクリック（`buttons`）

```json
"buttons": {
  "detail": { "state": true, "cond": "COUNTROW(明細)>0", "name": "明細を見る", "name_en": "Items" },
  "create": { "state": false, "cond": "1", "name": "明細を見る" },
  "update": { "state": true, "cond": "1", "name": "明細を見る" }
}
```

| キー | 中身 |
| --- | --- |
| `state` | その画面（`detail` = 詳細、`create` = 追加、`update` = 編集）にボタンを出す |
| `cond` | ボタンを出す条件の式。空だと出ない。いつも出すなら `"1"` |
| `name` | ボタンの字。`state` が `true` なら必須 |
| `name_en` / `name_ja` / `name_zh` | 言語ごとのボタンの字（空・省略なら `name`） |

- **`buttons` を省く、または画面を書かないと、その画面は「出す・条件 `1`・字は「概要確認」」になる**（設定画面の新しい行と同じ）。出さない画面は、`"state": false` と書く。
- 一覧の画面にはボタンを出せない。
- 行の外の設定の `menu` を有効にすると、ボタンを 1 つのメニューにまとめる。

## ステップ（`steps[]`）

| キー | 中身 |
| --- | --- |
| `state` | このステップを使う。省くと `true` |
| `desc` | 概要（ステップを見分ける名前。設定画面の要約に出る）。省くと「ステップ 1」のような名前 |
| `cond` | 表示条件の式。真のときだけ、このステップを出す。**空だと出ない**。いつも出すなら `"1"`（省くと `"1"`） |
| `dialog` | ダイアログを出す。省くと `true` |
| `icon` | アイコン。`info` / `success` / `error` / `warning` / `question`。省くと `info` |
| `title` | タイトルの式。空なら既定の文（保存 = 更新確認、アクション = 実行確認、ボタン = 概要確認） |
| `body` | 本文の式。結果の文字は **HTML として描かれる**（下の「本文の書き方」） |
| `notify` | 通知を使う（保存イベントとプロセスアクションだけ）。省くと `false` |
| `ok` | 通知 (OK) の式。全部 OK で保存・実行された後に出す通知。空なら既定の文（レコードを更新しました） |
| `cancel` | 通知 (Cancel) の式。このステップでキャンセルしたときに出すエラーの文。空なら「キャンセル」 |
| `title_en` `title_ja` `title_zh`、`body_…`、`ok_…`、`cancel_…` | 言語ごとの式。利用者の表示言語の欄が空（省略）なら、言語なしの式を使う |

- **`icon` が `error` のダイアログには OK のボタンが出ない**（キャンセルだけ = 必ず止まる）。条件に合うときに保存・アクションを止める使い方ができる。止める理由は `body` に、止めた後に画面に出す文は `notify: true` と `cancel` に書く。検査は warning（`step.errorIcon`）で知らせる（意図どおりなら、そのまま利用者に伝える）。
- `notify` が `false` のステップでキャンセルすると、エラーの文は「キャンセル」になる。`ok` と `cancel` は `notify` が `true` のときだけ使われる。
- `dialog: false`・`notify: true` のステップは、ダイアログを出さずに、保存・実行の後の通知だけを出す。
- **ボタンクリックの行では通知は出ない**（`notify` / `ok` / `cancel` は使われない。書くと warning）。最後のダイアログはボタンが「閉じる」だけになる。**ボタンクリックの行のステップは `notify: false` にする**（`true` のままだと、ダイアログを閉じたときに `cancel` の式が評価だけされる。値を書き換える関数が入っていれば、そこで動く）。
- 新しいステップの式の見本は、`cdlg_read` の `key: "new"` の雛形（保存イベントの既定の式）。書いていない式は空になる。
- 追加の画面の保存では、`$id`（レコード番号）は空。`IF($id, "更新します", "追加します")` のように書き分けられる。保存の後の通知（`ok`）では、追加したレコードの番号が入る。

### 本文の書き方（`body`）

- **文字をそのまま**: `"見積金額は " & FVAL(金額) & " です。<br>保存しますか？"`。`<br>` や `<b>…</b>` などのタグを書ける。**`&` でつないだ項目の値も HTML として読まれる**（値に `<` が入っていると、タグとして扱われて消える）。値に記号が入りうる項目は `ESC_HTML(項目)` で包む。
- **ボタンの字を変える**: `OPT("HTML", 本文, "OK", "このまま保存", "CANCEL", "戻る", "NEXT", "次の確認へ")`。`OK` = 最後のダイアログの OK、`NEXT` = 途中のダイアログの OK、`CANCEL` = キャンセル。書いたものだけ変わる。**字を `""` にすると、そのボタンを出さない**（`"OK", ""` と `"NEXT", ""` = 進めない = 必ず止まる）。**`"CANCEL", ""` はキャンセルのボタンを隠すだけ**で、× や Esc でダイアログを閉じれば、キャンセルと同じに止まる（止められないダイアログは作れない）。
- **タグを組み立てる**: `TAGS_HTML(TAG("p", "件名: " & 件名), TAG("p", "金額: ", TAG("strong", FVAL(金額))))`。
  - **`TAG(…)` だけを本文に書かない**（文字にならず、既定の本文「レコードを更新します」が出る）。必ず `TAGS_HTML(…)` で包む。
  - `TAG` の中の文字は、`<` `>` が文字として出る（タグにならない）。属性は `ATTR("class", "名前")` や `ATTR("style", "color:red")`。中身の無いタグは `VTAG("br")`。
  - 複数行の文字（複数行の項目）を改行つきで出すなら `TAG("p", HTML(FVAL(備考)))`（`FVAL` が改行を `<br>` にし、`HTML` がそのまま出す。**値の中のタグもそのまま効く**）。`TAG("p", 備考)` は、改行が空白として出る。
  - `HTML(…)` を `&` でつながない（`[object Object]` になる）。`TAG` の中に書く。
- **テーブルを表にする**: `TABLE_HTML(明細, ARRAY("#", ROWNO(明細)+1), 品名, 数量)`（`TAGS_HTML(…)` の中に書く。見出しは項目のラベル。`ARRAY("見出し", 式)` で列を足せる。`ROWNO` は 0 始まり）。
- **書式つきの値**: `FVAL(金額)` は、項目の設定（桁区切りなど）で整えた文字（`1,500,000`）。日付は `DATE_FORMAT(期限, "YYYY年M月D日")`。
- 本文の結果が数・真偽値のときは、既定の本文が出る（文字にする: `"" & 金額`）。空の式は、本文なし。
- ダイアログの幅などは、`TAGS_HTML` の先頭に `TAG("style", ".rex0220-cfdialog-dialog { --kuc-dialog-max-width: 800px; }")` を置くか、行の外の設定の共通 CSS に書く。

## 行の外の設定（`common`）

**書いたキーだけが取り込み用のファイルに入る。書いていないキーは、取り込んでもアプリの今の設定のまま。** 新しく作った設定ファイルの `common` は空（`{}`）で、今の設定を写した設定ファイルには今の値が入っている。変えたいものだけを書く（`cdlg_update` の `patchCommon`）。

| キー | 中身 |
| --- | --- |
| `pluginEnable` | プラグイン有効。`false` にすると、レコード画面で何もしない |
| `pluginComment` | NOTE（一言メモ。新しく書くなら 10,000 字まで） |
| `pluginDescription` | 説明（新しく書くなら 10,000 字まで） |
| `notifySeconds` | 通知を出しておく秒数。`"0"`〜`"10"` の**文字**（`"0"` は自動で消さない） |
| `menu` | メニュー表示。`{ "enabled": true, "label": { "default": "概要", "ja": "", "en": "Overview", "zh": "" } }`。`enabled` が `true` なら、ボタンクリックのボタンを 1 つのメニューにまとめる。`label.default` は必須（メニューの見出し）。言語ごとの見出しは空なら `default` |
| `css` | 共通 CSS。`{ "enabled": true, "rows": [{ "state": true, "name": "名前", "desc": "", "css": ".x { color: red; }" }] }`。`enabled` が `true` なら、ダイアログを出す間だけ「使う」の CSS を当てる。**`css` を書くと、有効と中身の両方が決まる**: `rows` を省くと既定の 4 つ（印刷屋プラグインと同じ名前のクラス `pcraft-…` の見た目）になり、`rows` を書くとその並びに入れ替わる |

- 「運用環境に反映」は設定ファイルに無い（取り込んだ後に、利用者が設定画面で決める）。

## 式の書き方

計算式プラグインと同じ式の言語です。項目は**項目コード**で書く（ラベルではない）。文字は `"…"`、文字をつなぐ `&`、等しい `=`、等しくない `!=`、`<` `<=` `>` `>=`、`AND(a,b,…)` `OR(a,b,…)` `NOT(a)` `IF(条件,真,偽)`。`//` から行末まではコメント。

**真と偽**（表示条件）: 式の結果が `true`、0 でない数、空でない文字なら真。`false`、`0`、空の文字 `""` は偽。

次の表は、プラグインと同じ計算式エンジンで確かめた書き方です（項目コードは例）。

| したいこと | 式 | 注意 |
| --- | --- | --- |
| 文字が等しい / 等しくない | `状況="完了"` / `状況!="完了"` | ドロップダウン・ラジオボタンも同じ。**選択肢の名前は `cdlg_fields` の `options` のとおりに** |
| どれかに等しい | `IN(状況,"完了","保留")` | |
| 文字を含む | `TEST(件名,"至急")` | |
| 空 / 空でない | `項目=""` / `項目!=""` | |
| 数値の比較 | `金額>=1000000` | **空の数値は 0 と同じに扱われる**（`金額<100` は空でも真）。空を除くなら `AND(金額!="",金額<100)` |
| 日付が今日より前 | `AND(期限!="",DATE_FORMAT(期限)<TODAY())` | 日付の項目をそのまま `TODAY()` と比べない（`DATE_FORMAT(期限)` で同じ形の文字にする）。空の日付は `DATE_FORMAT` が `""` になり `<TODAY()` が真になるので、`期限!=""` を付ける |
| 日付の計算 | `DATE_ADD(期限,-3,"days")`、`DATE_DIFF("TODAY",期限,"days")` | `DATE_ADD` は `"2099-12-28"` の形。`DATE_DIFF` は 2 つ目から 1 つ目を引いた日数（期限までの残りの日数） |
| テーブルの行数・合計 | `COUNTROW(明細)=0`、`SUM(数量)>=10` | テーブルの中の項目をそのまま書くと、先頭の行の値で評価される |
| テーブルのどれかの行が… | `AND(COUNTROW(明細)>0,MIN(数量)<=0)`（0 以下の行がある）、`MAX(数量)>=100`、`CONTAINS(品名,"板")`（どれかの行が等しい） | **`MIN` / `MAX` は、空の行を数えない**（数量が 3 と空なら `MIN` は 3）。行が無いと `""`。空の行も見るなら、別の条件にする |
| チェックボックス・複数選択に含む | `IN(区分,"A")`、何も選んでいない: `区分=""` | |
| ユーザー選択に自分が入っている | `IN(SEL_CODE(担当者,"array"),LOGIN_CODE())` | ユーザー選択の項目をそのまま書くと「名前, 名前」の文字になる（**名前で比べない**。同じ名前の人で誤る）。`SEL_CODE(項目,"array")` がログイン名の並び |
| 作成者が自分 | `SEL_CODE(作成者,"text")=LOGIN_CODE()` | |
| 追加か更新か | `IF($id, "更新します", "追加します")` | 追加の画面の保存では `$id` が空 |
| アクションの情報 | `EV_INFO("action")` / `EV_INFO("status")` / `EV_INFO("nextStatus")` | 実行するアクション名・今のステータス・次のステータス（**利用者の表示言語の名前**） |
| モバイルで分ける | `EV_INFO("mobile")`（モバイルなら真）、`NOT(EV_INFO("mobile"))` | |
| ログインユーザー | `LOGIN_CODE()`（ログイン名）、`LOGIN_NAME()`（表示名） | **`cdlg_try` では仮の利用者**（`LOGIN_CODE()` は仮のコード、`LOGIN_NAME()` は空）。「自分が入っている」側を確かめるなら、`probes` で `LOGIN_CODE()` の値を見て、自分で書くレコードのユーザー選択の `code` にその値を入れる。最後は画面で確かめてもらう |
| 一覧での編集の保存を見分ける | `EV_INFO("type")="app.record.index.edit.submit"` | 追加の画面は `"app.record.create.submit"`、編集の画面は `"app.record.edit.submit"`（モバイルは先頭に `mobile.`。モバイルに一覧での編集は無いので、`cdlg_try` の場面で `index` と `mobile` は一緒に書けない） |

- **式に `//` を書くと、そこから行末までがコメントとして除かれる。文字列の中でも除かれる**（URL を書くときは `"https:/" & "/example.com"` のように分ける）。
- **使えない関数**: `UINFO` / `OINFO` / `GINFO` / `OUSERS` / `GUSERS`（確認ダイアログはユーザー情報を読み込まない。検査で止まる）。
- **値を書き換える・画面を操作する関数**（`FSET` など）: 保存・アクションのときにレコードの値を書き換える（保存される値が変わる）。書けるが、検査が warning（`formula.sideEffect`）を出し、`cdlg_try` はその設定を模擬しない。利用者に頼まれたときだけ書く。
- **式に書けない名前**: `constructor` / `toString` / `valueOf` / `hasOwnProperty` / `__proto__` など（検査で止まる）。
- **一覧での編集の保存**（保存イベントの `update` に含まれる）: kintone の決まりで、**計算の項目の値は、その一覧に置いてあれば空、置いてなければ再計算の前の値**になる（編集の画面の保存では、計算した値）。計算の項目（合計など）を条件に使う行は、一覧での編集では出ない・古い値で判定することがある（空の値は、数の比較では 0 と同じ = `合計>=1000000` は偽）。**テーブルは、一覧に置いてあってもなくても、全部の行が渡る**（`COUNTROW`・`SUM`・`MIN` は編集の画面と同じに働く。テーブルの中の計算の項目は確かめていない）。`cdlg_try` の `index` の場面は、渡したレコードの値のまま評価するので、この違いは出ない。一覧での編集では確かめない・止めないなら、条件に `EV_INFO("type")!="app.record.index.edit.submit"` を足す。保存を止める行（アイコン error）を計算の項目の条件で作ったときは、**一覧での編集で保存できるかを、利用者に画面で確かめてもらう**（必ず伝える）。
- 書いた式は、必ず `cdlg_try` で、出るレコードと出ないレコードを当てて確かめる。関数の名前を推し量らない（無い関数は検査で `FIELD CODE NOT FOUND` になる）。表に無い書き方は、`probes` で値を見てから使う。

## 検査の指摘（`cdlg_check`）

`error` は直すまで取り込み用のファイルを作れない。`warning` は作れるが、利用者に伝える。`rowKey` は設定ファイルの行のキー（行の外は `common`）、`section` は `steps[1]`（1 始まり）・`buttons.detail`・`actions` など、`label` は式のキー（`cond` / `title` / `body` / `ok` / `cancel`）など。

| code | 意味 |
| --- | --- |
| `key.unknown` | 知らないキー（綴り違い）。`label` にキーの名前、`message` に書けるキーの一覧 |
| `name.required` | `state` が `true` の行に `name` が無い |
| `event` | `event` が `save` / `process` / `button` でない |
| `formula` | `state` が `true` の行・ステップ・ボタンの式を評価できない（無い項目コード、文法、使えない関数）。`message` がエンジンの文 |
| `disabled.formula`（warning） | `state` が `false` の行・ステップ・ボタンの式の誤り（取り込める。使うなら直す） |
| `formula.reserved` | 式に書けない名前を書いた |
| `formula.sideEffect`（warning） | 値を書き換える・画面を操作する関数を使っている（保存・アクションのときにレコードの値が変わる）。**必ず利用者に伝える** |
| `cond.empty`（warning） | 表示条件が空（出ない）。いつも出すなら `"1"` |
| `icon` | `icon` が候補に無い |
| `button.name` / `buttons.screen` | 「使う」のボタンに `name` が無い / `buttons` のキーが `detail` / `create` / `update` でない |
| `actions` | `actions` の形が `[{ name, from, to }]` でない |
| `action.notFound`（warning） | アプリのプロセス管理に無いアクション（レコード画面では使われない） |
| `process.disabled`（warning） | アプリのプロセス管理が無効（プロセスアクションの行は動かない） |
| `status.unavailable`（warning） | プロセス管理を読めなかったので、アクションを確かめていない（アプリ管理の権限が要る） |
| `actions.none` / `save.none` / `buttons.none` / `steps.none`（warning） | 「使う」の行だが、アクション / 画面 / 「使う」のボタン / 「使う」のステップが無い（何も出ない） |
| `step.nothing`（warning） | `dialog` も `notify` も `false`（何も出さないステップ） |
| `step.notifyButton`（warning） | ボタンクリックの行で `notify` が `true`（通知は出ない） |
| `step.errorIcon`（warning） | `icon` が `error` のダイアログ（OK のボタンが出ない = 必ず止まる） |
| `notifySeconds` / `menu` / `css` | 行の外の設定の形の誤り |
| `text.tooLong`（warning） | NOTE・説明が 10,000 字を超える（そのまま取り込めるが、設定画面では書き足せない） |
| `type.boolean` / `type.string` / `type.object` / `type.array` | 形の誤り |

検査は、式を**架空のレコード**で評価する（文法と、項目があるかまで）。条件が真になるかどうかは見ない。指摘が 100 件を超えると、error を先にして先頭の 100 件だけが返る（`issuesTotal` に全部の数）。

## 模擬の結果（`cdlg_try`）

レコードと場面を当てて、レコード画面と同じ順に式を評価した結果です。

- `status: "too-large"` は、結果が大きすぎて返していない（60,000 字まで）。`scenes` を減らす、`html` を外す、`probes` を減らす、レコードを減らす。知らない入力（綴り違い、ほかの製品の入力）は、受ける前に断る。`status: "no-records"` は、条件に合うレコードが無い。設定に error があるとき・値を書き換える関数がある式があるとき（`simulate.sideEffect`）は `has-errors`（模擬していない）。
- `results[]`: レコード × 場面ごと。`record` はレコード番号（`$id` の無いレコードは `#1` のように渡した順）、`scene` は渡した場面。
- 保存・アクションの場面:
  - `dialogs[]`: **全部 OK を押したときに出るダイアログの並び**。空なら、何も出ない（そのまま保存・実行される）。
    - `row` = 行のキー、`step` = ステップの番号（1 始まり）、`icon`、`title`、`text` = 本文を文字にしたもの（300 字まで。`<br>` は改行）、`ok` / `cancel` = ボタンの字（`null` = そのボタンは出ない）、`last` = 最後のダイアログか（最後でなければ OK は「次へ」）。
    - `onCancel` = そこでキャンセルしたとき（キャンセルのボタン・×・Esc）の結果。`{ "error": "文" }` = その文をエラーとして出して止まる（保存・実行されない）。**キャンセルのボタンを出さないダイアログ（`cancel` が `null`）にも付く**（閉じればキャンセルになる）。ボタンの場面では `{ "stopped": true }`（閉じるだけ）。
    - `ok` が `null` のダイアログ（アイコン error など）は必ず止まるので、並びはそこで終わる。
  - `notices[]`: 全部 OK を押して保存・実行された後に出る通知。途中で必ず止まるときは空で、`stoppedWith` に止まったときのエラーの文。
  - **追加の場面（`create`）で `$id` の無いレコードを当てると、保存の後の通知の `$id` は `1`**（仮の番号）。
  - アクションの場面の `note`: そのアクションが、どの行でも選ばれていない（レコード画面では何も出ない）。
- ボタンの場面:
  - `buttons[]`: その画面に出るボタン（表示条件が真のもの）。`row`、`label` = ボタンの字、`dialogs` = 押したときに出るダイアログの並び。空なら、ボタンは出ない。
  - `menu`: メニュー表示が有効なときの、メニューの見出し。
- `errors[]`: 評価できなかった式（`row`、`step`、`at` = `cond`〈表示条件〉/ `dialog`〈タイトル・本文・通知 (Cancel)〉/ `ok`〈通知 (OK)〉、`message`）。**レコード画面では、表示条件が評価できないステップ・ボタンは出ない。タイトル・本文が評価できないステップは飛ばされる。エラーの知らせは出ない**。
- `probes` を渡すと、`results[]` のそれぞれに `probes[]` が入る（渡した順）。`formula`、`value`（式の値。文字は 300 字まで。文字・数・真偽値以外は JSON の文字にしたもの）、`type`（`string` / `number` / `boolean` / `object` / `array` / `null`。値が無いときは `value` が `null`・`type` が `null`）。評価できなかった式は `error`（エンジンの文）。その場面のイベントで評価する（`EV_INFO` はその場面の値）。値を書き換える関数は書けない。
- `html: true` を渡すと、`dialogs` に `html`（本文の HTML。4,000 字まで）が入る。タグの組み立てを確かめるときだけ使う（大きくなる）。
- `crash`: そのレコード・場面の模擬が止まった（式を見直す）。
- **模擬が見ないこと**: 編集の画面の保存とアクションの実行の前の「他の利用者の更新」の確かめ（本物は、レコードが他で更新されていれば知らせを出して、確認ダイアログを出さない）。模擬は、いつも更新されていないものとして答える。
