# 項目書式: 設定ファイルの書き方

`ffmt_*` のツールが読み書きする設定ファイル（元の値）の形です。項目書式プラグイン Ver.16 以降。設定画面の「設定をダウンロード」のファイルとは形が違います（`ffmt_new` の `from` で写す）。

```json
{
  "common": {
    "listInfo": { "all_enabled": false, "views": { "20": "(すべて)" } }
  },
  "rows": [
    {
      "key": "01", "state": true, "field": "期限", "detail": true, "list": true,
      "label": [],
      "value": [
        { "state": true, "formula": "AND(期限!=\"\",DATE_FORMAT(期限)<TODAY())", "theme": "", "color": "#ffffff", "bcolor": "#ff0000", "fsize": "", "fstyle": "bold" }
      ]
    }
  ]
}
```

## 行（`rows[]`）— 1 項目に 1 行

| キー | 中身 |
| --- | --- |
| `key` | 行のキー（"01"…。位置で決まる。書かなくてよい） |
| `state` | この行の設定を使う。`false` の行には書式を付けない（設定は残る） |
| `field` | 項目コード。**1 項目に 1 行**（同じ項目の行を 2 つ書けない） |
| `detail` | レコードの詳細画面と印刷画面で書式を付ける（モバイルは詳細画面） |
| `list` | 一覧画面で**値の書式**を付ける（ラベルの書式は一覧画面には付かない） |
| `label` | ラベルの書式の条件の並び |
| `value` | 値の書式の条件の並び |

- 書式が付くのは、詳細・印刷・一覧の画面。**編集・追加の画面には付かない**。
- 行の並びに意味は無い（取り込むと、設定画面はフォームの順に並べる）。
- 行を書ける項目: レコード番号、文字列（1 行・複数行）、リッチエディター、数値、計算、日付・時刻・日時、ドロップダウン、ラジオボタン、チェックボックス、複数選択、ユーザー選択・組織選択・グループ選択、リンク、添付ファイル、作成者・更新者、作成日時・更新日時、**テーブル**（テーブルの行。`field` はテーブルのコード）、テーブルの中の項目、グループの中の項目。書けない項目: グループ自身、関連レコード一覧、ラベル・スペース・罫線、カテゴリー。
- プロセス管理が有効なアプリでは、**ステータス**（タイプ STATUS の項目コード）、**作業者**（STATUS_ASSIGNEE）、**ステータスの履歴**（`field` は `$STATUS_HISTORY`。ラベルの書式だけ。値の書式は書けない）にも行を書ける。

### テーブル

- テーブルの行（`field` = テーブルのコード）: ラベルの書式は**全部の列の見出し**、値の書式は**その行の全部のセル**に付く。値の書式の式は行ごとに評価する（行の項目をコードで書く）。
- テーブルの中の項目（`field` = 子のコード）: ラベルの書式はその列の見出し、値の書式はその列のセルに付く。式は行ごとに評価する。
- 両方にあって同じセルに当たるときは、設定画面の表で後にある行の書式になる（ふつうはテーブルの行が先、子が後 = 子が勝つ）。
- 一覧画面では、テーブルを開いたときに行の書式が付く。モバイルの一覧画面にテーブルの行の書式は付かない。

## 条件（`label[]` / `value[]`）

**上から順に確かめ、最初に真になった条件の書式だけを付ける。** 並びに意味がある（厳しい条件を上に）。

| キー | 中身 |
| --- | --- |
| `state` | この条件を使う。`false` の条件は飛ばす |
| `formula` | 条件の式。`state` が `true` なら必須。いつも付けるなら `1` |
| `color` | 文字色。`#rrggbb`（`#rgb` と、`#` の無い形も受けて `#rrggbb` に直す）。空なら付けない。**色の名前（red など）や rgb(...) は書けない** |
| `bcolor` | 背景色。同じ形 |
| `fsize` | 文字サイズ。`x-small` / `small` / `large` / `x-large`（小さい / やや小さい / やや大きい / 大きい）か、`1`〜`99` の整数（px）。空なら変えない |
| `fstyle` | 文字修飾。`bold`（太字）/ `underline`（下線）/ `line-through`（打ち消し線）。1 つだけ。空なら変えない |
| `theme` | 設定画面の「テーマ」の列の値（背景色と文字色の組の覚え。表示用）。**新しい条件では空でよい**。色は `color` と `bcolor` に書く |
| `rid` | 設定画面が付けた番号。**読み込んだ値のままにする**（消さない・変えない）。新しい条件には書かない |

- 真になる条件が無ければ、書式は付かない（kintone の標準の見た目）。「それ以外」の書式が要るなら、最後に `formula: "1"` の条件を置く。
- 色・大きさ・修飾は、書いたものだけが付く（`color` だけ書けば文字色だけ変わる）。
- リンク・ユーザー選択・組織選択・グループ選択・添付ファイルの値の文字色は、中のリンクの文字に付く。
- 見やすい組み合わせ（設定画面のテーマの表から。背景色 → 文字色）: 濃い色 `#ff0000` `#0000ff` `#008000` `#ff8c00` `#a52a2a` `#000000` `#808080` → `#ffffff`、黄 `#ffff00` → `#0000ff`、淡い色 `#ffc0cb` `#ffd07b` `#d6d6ac` `#a4b2da` `#8ebcb0` `#d3d3d3` → `#000000`。

## 行の外の設定（`common`）

**書いたキーだけが取り込み用のファイルに入る。書いていないキーは、取り込んでもアプリの今の設定のまま。** 新しく作った設定ファイルの `common` は空（`{}`）で、今の設定を写した設定ファイル（`ffmt_new` の `from`）には今の値が入っている。変えたいものだけを書く（`ffmt_update` の `patchCommon`）。

| キー | 中身 |
| --- | --- |
| `pluginEnable` | プラグイン有効。`false` にすると、レコードの画面で何もしない |
| `pluginComment` | NOTE（一言メモ。10,000 字まで） |
| `pluginDescription` | 説明（10,000 字まで） |
| `listInfo.all_enabled` | `true` = 全部の一覧で書式を付ける。`false` = `views` の一覧だけ |
| `listInfo.views` | `{ "一覧の ID": "名前" }`。表形式の一覧だけ。「(すべて)」の一覧の ID は `20`。名前は、検査のときに今の一覧の名前に直る |

- 一覧の ID は推測しない。`ffmt_fields` の `views`（`type` が `LIST` のもの）で確かめる。読めないとき（`viewsNote`）は、今の設定の値を使うか、利用者に聞く。アプリに無い ID は、選択を残して warning で知らせる。
- 「運用環境に反映」は設定ファイルに無い（取り込んだ後に、利用者が設定画面で決める）。
- 設定画面の取り込みの「共通の設定」（一覧別設定 / 説明・NOTE・プラグイン有効 / 運用環境に反映）は、**最初から全部にチェックが入っている**。ファイルに入っているキーは、どちらの取り込み方でもファイルの値になる。利用者が今の値を残したいなら、その群のチェックを外してもらう（`ffmt_export` の `nextSteps` に、ファイルに何が入っているかが出る）。

## 式の書き方

計算式プラグインと同じ式の言語です。項目は**項目コード**で書く（ラベルではない）。文字は `"…"`、等しい `=`、等しくない `!=`、`<` `<=` `>` `>=`、`AND(a,b,…)` `OR(a,b,…)` `NOT(a)` `IF(条件,真,偽)`。`//` から行末まではコメント。

**真と偽**: 式の結果が `true`、0 でない数、空でない文字なら真。`false`、`0`、空の文字 `""` は偽。`"0"` や `"false"` という**文字**は真。条件は比較（`=` `<` など）か `AND` / `OR` / `TEST` / `IN` のように真偽を返す形で書く。

次の表は、プラグインと同じ計算式エンジンで確かめた書き方です（項目コードは例）。

| したいこと | 式 | 注意 |
| --- | --- | --- |
| 文字が等しい | `状況="完了"` | ドロップダウン・ラジオボタン・ステータスも同じ。**選択肢の名前は `ffmt_fields` の `options` のとおりに** |
| どれかに等しい | `IN(状況,"完了","保留")` | |
| 文字を含む | `TEST(件名,"至急")` | `FIND(件名,"至急")` は位置を返し、無いときは `-1`（= 真）なので、条件にそのまま書かない（`FIND(件名,"至急")>=0`） |
| 先頭が一致（正規表現） | `SEARCH(件名,"^至急")>=0` | |
| 空 / 空でない | `項目=""` / `項目!=""` | 文字・数値・日付・ドロップダウン・チェックボックス・ユーザー選択のどれでも |
| 数値の比較 | `金額>=1000`、`AND(金額>=100,金額<1000)` | **空の数値は 0 と同じに扱われる**（`金額<100`・`金額=0`・`金額>=0` は空でも真）。空を除くなら `AND(金額!="",金額<100)` |
| 日付が今日より前 | `AND(期限!="",DATE_FORMAT(期限)<TODAY())` | **日付の項目をそのまま `TODAY()` と比べない**（`期限<TODAY()` はいつも偽。日付の項目は数、`TODAY()` は `"2026-11-20"` の形の文字）。`DATE_FORMAT(期限)` で同じ形の文字にする。**空の日付は `DATE_FORMAT` が `""` になり、`<TODAY()` が真になる**ので、`期限!=""` を付ける |
| 日付が今日 | `DATE_FORMAT(期限)=TODAY()` | |
| 今日から 3 日以内 | `AND(期限!="",DATE_FORMAT(期限)>=TODAY(),DATE_FORMAT(期限)<=DATE_ADD(TODAY(),3,"days"))` | `DATE_ADD(TODAY(),3,"days")` は `"2026-11-23"` の形 |
| 日付の差（日数） | `DATE_DIFF(期限,"TODAY","days")>0` | 2 つ目から 1 つ目を引いた日数（期限が昨日なら 1）。単位は `"days"` `"months"` `"years"` など |
| 今月 | `DATE_FORMAT(日付,"YYYY-MM")=DATE_FORMAT(TODAY(),"YYYY-MM")` | |
| 土日 | `IN(DATE_FORMAT(日付,"d"),"0","6")` | `"d"` は曜日の番号（日 = 0 … 土 = 6） |
| 日時 | `DATE_FORMAT(日時,"YYYY-MM-DD")<TODAY()` | 日時の項目は `"2026-11-01 12:00"` の形の文字。日付だけ比べるなら `DATE_FORMAT` で切る |
| チェックボックス・複数選択に含む | `IN(区分,"A")`（どれかを含む: `IN(区分,"A","B")`） | |
| ユーザー選択に自分が入っている | `IN(SEL_CODE(担当者,"array"),LOGIN_CODE())` | `ffmt_try` はツールの既定の利用者で評価する。画面で確かめてもらう |
| 作成者が自分 | `SEL_CODE(作成者,"text")=LOGIN_CODE()` | |
| ステータス | `ステータス="完了"`、`IN(ステータス,"処理中","完了")` | ステータスの項目コードは `ffmt_fields` で確かめる。**ステータスの名前はツールでは一覧にできない**。利用者に聞くか、`ffmt_try` の `probes` で今のレコードの値を見る |
| テーブルの行の値 | `数量>=10`（テーブルの行・子の値の書式で、その行の `数量`） | 行の外の項目も書ける（`AND(数量>=10,金額>=1000)`） |
| テーブルの行の番号 | `MOD(ROWNO(明細),2)=1` | `ROWNO(テーブル)` は 0 始まり（偶数番目の行に付けるなら `=1`） |
| テーブルの合計・行数（テーブルの外の項目の条件で） | `SUM(数量)>=10`、`COUNTROW(明細)=0` | |
| 画面で分ける | `EV_INFO("mobile")`（モバイルなら真）、`EV_INFO("cate")="detail"`（詳細画面） | 一覧画面では `EV_INFO("type")` と `EV_INFO("cate")` は空の文字になる。詳細と一覧で分けるだけなら、行の `detail` / `list` を使う |

- **使えない関数**: `UINFO` / `OINFO` / `GINFO` / `OUSERS` / `GUSERS`（項目書式はユーザー情報を読み込まない。検査で止まる）。値を書き換える関数（`FSET` / `BUTTON` / `DIALOG` など）も条件に書かない。
- テーブルの中の項目を、テーブルの外の項目の条件にそのまま書くと、**先頭の行の値**で評価される（`数量>=10` は 1 行目だけを見る）。テーブル全体を見るなら、`SUM(数量)` / `MAX(数量)` / `COUNTROW(明細)` / `CONTAINS(品名,"値")`（どれかの行にある）のような関数で書く。
- 書いた式は、必ず `ffmt_try` で、真になるレコードとならないレコードを当てて確かめる。

## 検査の指摘（`ffmt_check`）

`error` は直すまで取り込み用のファイルを作れない。`warning` は作れるが、利用者に伝える。`rowKey` は設定ファイルの行のキー、`section` は `label` / `value` など、`label` は条件の番号（1 始まり）か項目コード。

| code | 意味 |
| --- | --- |
| `field.required` / `field.notFound` / `field.type` / `field.duplicate` | `field` が空 / アプリに無い / 書式を付けられない項目 / 同じ項目の行が 2 つ |
| `disabled.field.notFound`（warning） | `state: false` の行の項目がアプリに無い（取り込み用のファイルに入らない） |
| `formula.required` / `formula.invalid` | `state: true` の条件の式が空 / 評価できない（無い項目コード、文法、使えない関数）。`message` がエンジンの文 |
| `disabled.formula.*`（warning） | `state: false` の行の中の、式の誤り |
| `color.format` / `fstyle.format` | 色が `#rrggbb` でない / 文字修飾が候補に無い |
| `fsize.loose`（warning） | 文字サイズが設定画面で入れられる値でない（そのまま取り込めるが、設定画面では入れ直せない） |
| `cond.array` / `cond.object` / `cond.boolean` / `cond.string` / `cond.rid` / `row.boolean` | 形の誤り |
| `statusHistory.value` | ステータスの履歴に値の書式を書いた |
| `row.noCond`（warning） | 行の `state` が `true` だが、有効な条件が無い |
| `row.noScreen`（warning） | 行の `state` が `true` だが、`detail` も `list` も `false` |
| `common.*` / `listInfo.shape` / `view.id` | 行の外の設定の形の誤り |
| `view.notFound` / `views.unavailable` / `view.none`（warning） | アプリに無い一覧 / 一覧を読めず確かめていない / `all_enabled` が `false` で一覧が 1 つも無い |

検査は、式を**架空のレコード**で評価する（文法と、項目があるかまで）。条件が真になるかどうかは見ない。

## 模擬の結果（`ffmt_try`）

レコードを当てて、レコード画面と同じ順に式を評価した結果です。

- `records[]`: レコードごと。`id` はレコード番号。`screens` に画面ごとの答え（`detail` = PC の詳細、`print` = 印刷、`list` = PC の一覧、`mobileDetail`・`mobileList` = モバイル。省くと `detail` と `list`）。
  - 画面ごとの答えは `{ 項目コード: { "label": 番号, "value": 番号 } }`。**番号 = 選ばれた条件（1 始まり。0 = どれも付かない）**。`label` = ラベルの書式、`value` = 値の書式。
  - テーブルの行と子の値の書式は、行ごとの並び（`"value": [1, 0]` = 1 行目は条件 1、2 行目は付かない）。行が無ければ `value` は出ない。一覧の画面に `label` は無い。
  - 行の `state` が `false` の項目、その画面の指定（`detail` / `list`）が `false` の項目、レコードに無い項目は出ない。
  - 設定の行が多いときは、`fields` に確かめたい項目コードを渡して絞る（`conditions` も絞られる）。
- `conditions[]`: `state` が `true` の条件ごと（行の `state` も `true` のもの）。**その条件だけ**を PC の詳細の呼び方で評価した結果（上の条件が先に選ばれるかどうかとは別）。
  - `total` = 評価した回数（レコードの数。テーブルの値の書式は行の数）、`hits` = 真の数、`errors` = 例外の数（`firstError` に文。**レコード画面では例外の条件は飛ばされ、書式は付かない**）、`samples` = 例（真・偽・例外を 1 つずつ、3 つまで。`record`、`row`、`truth`、式の値 `value` と型 `type`）。
  - `hits` が 0 の条件は、当てたレコードでは一度も真にならない。式の誤り（日付の比べ方、選択肢の名前）か、たまたま合うレコードが無いだけかを、`samples` の値で見分ける。
- `probes[]`（`probes` を渡したとき）: 設定に入れずに評価した式ごと。`formula`、`field`（渡したとき）、`total` / `hits` / `errors`、`samples`（レコードごと・行ごとの値）。**項目の今の値を見るなら、`formula` に項目コードだけを書く**（`{ "formula": "ステータス" }`、`{ "formula": "DATE_FORMAT(期限)" }`）。`field` を書くと、その項目の値の書式の条件と同じ文脈で評価する（テーブルの中の項目・テーブルなら行ごと）。設定ファイルが空でも使える。
- 当たる先の要素が画面に無いとき（作業者がいないレコードの作業者、権限で見えない項目など）は、条件が選ばれても何も付かない。
- `listInfo`: 一覧の書式は、`all_enabled` が `true` か、`views` にある一覧でだけ付く（模擬は一覧を見分けない）。`pluginEnable` が `false` なら、レコードの画面では何も付かない。
- 式の中の今日の日付はツールを動かした日、ログインユーザーはツールの既定の利用者。テーブルの行と子の両方に書式があるときの重なり（どちらが勝つか）は見ない。画面での見え方そのものは確かめていない。
