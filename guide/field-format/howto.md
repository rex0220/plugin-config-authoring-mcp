# 項目書式: 作業手順

項目書式プラグイン（Ver.16 以降）の設定を、要件から作る・今の設定を直すときの手順です。ツールは `ffmt_*`。**kintone には何も書きません。** 作るのは作業フォルダーのファイルで、設定画面への読み込みと保存は利用者が行います。

項目書式は、**条件の式が真のときに、その項目のラベルと値に書式（文字色・背景色・文字サイズ・文字修飾）を付ける**プラグインです。レコードの値は変えません。

## 始める前に

1. `ffmt_status` で、プラグインの zip と kintone の接続が読めるかを確かめる。`problem` や `not-configured` があれば、利用者に設定を頼む（zip の場所、接続のファイル）。自分で直そうとしない。
   - **接続の profile を確かめる**。`kintone.profileSelection` が `locked` なら、使う profile は起動の設定で 1 つに決まっている（`profile` の引数は書かない）。
   - `tool-selectable` で `profiles` が 2 つ以上あるときは、**kintone を読むツール（`ffmt_fields` / `ffmt_check` / `ffmt_try` / `ffmt_export`）を呼ぶ前に、どの profile を使うかを利用者に確かめる**。名前から環境を推し量らない。
2. 作る前に、利用者の頼みが項目書式に向いているかを確かめる。
   - **向いている**: レコードの値に応じて、項目の見た目（色・大きさ・太字など）を変える。期限切れを赤く、状況ごとに色分け、金額の大きい行を目立たせる、など。
   - **向いていない**: 値を計算して入れる（計算式プラグイン）、入力を止める・必須にする（項目検証プラグイン）、項目を隠す・並べ替える、編集画面・追加画面の見た目（書式が付くのは詳細・印刷・一覧だけ）、項目の中の文字の一部だけに色を付ける。向いていなければ、作る前にそう伝える。

## 新しく作る

1. **項目を確かめる**。`ffmt_fields`（`app` = アプリの番号、`preview: true`）で、項目コード・タイプ・ラベル・テーブル・選択肢（`options`）と、一覧（`views`）を読む。項目コードと選択肢の名前、一覧の ID は推測しない。
2. **設定ファイルを作る**。`ffmt_new`（`file` と `app`）。
3. **行を足す**。1 項目に 1 行。`ffmt_read` の `key: "new"` で行の雛形を取り、`field` に項目コード、`label`（ラベルの書式）と `value`（値の書式）に条件を入れて、`ffmt_update` の `addRow` で足す。書き方と、式の落とし穴は `ffmt_docs` の `spec`。
4. **検査する**。`ffmt_check`。`error` を直して、もう一度検査する。指摘はそのまま利用者に伝える。
5. **レコードを当てて確かめる**。`ffmt_try`（次の節）。検査は式の文法と項目があるかまでしか見ない。**条件が思ったとおりに選ばれるかは、ここで確かめる**。
6. **取り込み用のファイルを作る**。`ffmt_export`（`expectedDigest` は `ffmt_check` か `ffmt_try` が返した設定ファイルの digest）。返った `nextSteps` を利用者に伝える。

## レコードを当てて確かめる（`ffmt_try`）

- 利用者に、確かめるレコードを聞く。**書式が付くはずのレコードと、付かないはずのレコードの両方**（レコード番号 `ids`、または条件 `query`）。分からなければ `query` を省いた形（空の文字）で新しい順の数件を当てる。
- 空の値・境目の値（ちょうど 100、今日の日付など）は、`records` に自分でレコードを書いて当てる（kintone の REST の形。`{ "項目コード": { "type": "NUMBER", "value": "100" } }`。テーブルは `{ "type": "SUBTABLE", "value": [{ "id": "1", "value": { 子のコード: { type, value } } }] }`）。
- **条件を書く前に、項目の値の形を見たいとき**は `probes` を使う（`probes: [{ "formula": "ステータス" }, { "formula": "DATE_FORMAT(期限)" }]`。設定に入れずに、式の値だけが返る）。確かめるための設定ファイルを別に作らない。
- `status: "no-records"` は、条件に合うレコードが無かった（誤りではない）。`query` を見直すか、`records` に自分で書いて当てる。
- 結果の読み方は `spec` の「模擬の結果」。見る所:
  - `conditions` の `hits` が 0 の条件（当てたレコードでは一度も真にならない）、`errors` が 1 以上の条件（例外。レコード画面では書式が付かない）。`samples` に式の値が出る。
  - `records` の画面ごと・項目ごとの答え（選ばれた条件の番号。0 = どれも付かない）が、利用者の期待と合うか。設定の行が多いときは `fields` で、確かめたい項目に絞る。
- 合わなければ式を直し、`ffmt_check` → `ffmt_try` をやり直す。期待と合ったことを利用者に伝える（どのレコードで確かめたかも）。
- 確かめられないこと: 画面での見え方そのもの（要素に書式が付くこと）、ログインユーザーに依る条件（ツールの既定の利用者で評価する）、明日以降の日付での動き。これらは利用者に、保存の後に画面で確かめてもらう。

## 今の設定を直す

1. 利用者に、設定画面の「設定をダウンロード」で今の設定をファイルに出して、作業フォルダーの直下に置いてもらう。
2. `ffmt_files` でそのファイルを確かめ、`ffmt_new` の `from` に渡して設定ファイルにする（元のファイルは残る）。
3. `ffmt_read` で要約と行を読み、直す所を利用者と確かめてから `ffmt_update` で直す。条件を 1 つ足す・直すときは、行を読み、`label` か `value` の並びを直して `patchRow` で入れる（並びは丸ごと入れ替わる）。**触らない条件の `rid` は消さない**。
4. `ffmt_diff` で、直す前の設定ファイルとの差を確かめる（直す前のものを別の名前で `ffmt_new` の `from` から作っておくと比べられる）。
5. `ffmt_check` → `ffmt_try` → `ffmt_export`。

## 直すときの決まり

- `ffmt_update` は、`ffmt_read` で読んだ digest を `expectedDigest` に渡す。`conflict` が返ったら、読み直してからやり直す。ほかのツールでファイルを書き換えない。
- 行を足す・消す・動かすと、行のキーは位置で振り直る。続けて直すときは、返った `rows` のキーを使う。行の並びに意味は無い（設定画面はフォームの順に並べる）。
- **条件の並びには意味がある**（上から確かめて、最初に真になった条件だけが効く）。条件を足すときは、どこに入れるかを考える。
- 一覧の ID は推測しない。`ffmt_fields` の `views` で確かめる（読めなければ、今の設定の値を使うか、利用者に聞く）。
- 使わなくなった書式は、行を消すか、行の `state` を `false` にする（設定は残る）。どちらにするかは利用者に聞く。

## 最後に必ず伝えること

- kintone には何も書いていない。反映は、設定画面で「設定をアップロード」→ 取り込み方（**全置換** / **項目の置換**）→「保存する」（運用環境に反映）。
  - 全置換: 項目の設定を全部ファイルの内容にする。**ファイルに無い項目の設定は消える**。今の設定を写して作ったファイルならこちら。
  - 項目の置換: チェックした項目だけをファイルの内容にする。ほかの項目は今のまま。新しく足した・直した項目だけを入れるならこちら。
  - 今の設定を写したか分からないときは、両方の場合を書く。
- 取り込みの画面の「共通の設定」（一覧別設定 / 説明・NOTE・プラグイン有効 / 運用環境に反映）は、最初から全部にチェックが入っている。**設定ファイルの `common` に書いたものは、どちらの取り込み方でもファイルの値に置き換わる**。今の値を残したい群は、チェックを外してもらう。`common` に書いていないものは、チェックが入っていても今のまま（`ffmt_export` の `nextSteps` に、ファイルに何が入っているかが出るので、そのまま伝える）。
- 既存のレコードの値は変わらない。書式は、保存（とアプリの更新）の後、レコードを表示したときに付く。
- `ffmt_try` で確かめたレコードと結果。確かめていないこと（画面での見え方、ログインユーザーに依る条件）。
- warning の指摘があれば、消さずに伝える。
