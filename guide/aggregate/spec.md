# アプリ集計: 設定ファイルの書き方

`agg_*` のツールが読み書きする**設定ファイル**の形です。設定画面の保存値より小さい形で、項目は**項目コード**で指します。表示名・型・式が使う項目などは、検査（`agg_check` / `agg_export`）が kintone の項目定義から組み立てます。

- 設定ファイルは `agg_new` で作り、`agg_read` で読み、`agg_update` で直します。ほかの方法で書き換えません。
- 設定画面で読み込めるのは、`agg_export` が作る**取り込み用のファイル**です（設定ファイルそのものは読み込めません）。

## 用語

| 言葉 | 意味 |
|---|---|
| 自アプリ | プラグインを入れるアプリ。集計した値を入れる側（集計先） |
| 対象アプリ | 集計するレコードがあるアプリ（集計元）。行ごとに決める |
| 行 | 集計の処理 1 つ（設定画面の主グリッドの 1 行）。行ごとに対象アプリ・条件・集計項目などを持つ |

## 全体の形

```json
{
  "common": { … 行の外の設定 … },
  "rows": [ { … 行 … }, … ]
}
```

行のキー（`"01"`、`"02"` …）は位置で決まり、行を足す・消す・動かすと振り直ります。

## 式を書く場所と、使える項目（取り違えない）

式は計算式プラグインと同じ言語です。**場所によって、書ける項目のアプリが違います。**

| 場所 | 書ける項目 | 補足 |
|---|---|---|
| 対象アプリ条件の条件値（`filters[].value`） | **自アプリ**の項目 | 自アプリのレコードから作る値。`in` / `not in` は配列を返す式 |
| 集計項目の式（`fields[].formula`） | **対象アプリ**の項目 | 自アプリの項目は `#項目コード` で書く。`$sno` は集計するレコードの連番 |
| テーブル項目の式（`table.items[].formula`、`table.loop`、`table.out`） | **対象アプリ**の項目 | 同上。ループ配列を使うとき、配列の値は `$val` |
| 反映の式（`reflect.items[].formula`、`reflect.cond`） | **自アプリ**の項目 | テーブル項目に出した行の項目も使える |
| 実行条件（`common.executeCondition.formula`） | **自アプリ**の項目 | |

取り違えると、検査が `getVal FIELD CODE NOT FOUND: …` で止めます。

## 行

```json
{
  "state": true,
  "name": "受注の合計",
  "app": { "id": "", "fcode": "得意先LU" },
  "orFrom": null,
  "filters": [ { "state": true, "field": "顧客", "cond": "=", "value": "得意先CD" } ],
  "order": [ { "state": true, "field": "$id", "order": "desc" } ],
  "fields": [ { "state": true, "to": "合計", "summary": "sum", "formula": "金額", "init": true, "editable": false } ],
  "table": { "enabled": false, "to": "", "from": "", "delrowDisabled": false, "hideRecid": false, "totalling": false,
             "loop": { "state": false, "formula": "ARRAY(0)" }, "out": { "state": false, "formula": "1" }, "items": [] },
  "reflect": { "cond": { "state": false, "formula": "1" }, "items": [] }
}
```

行の雛形は `agg_read` の `key: "new"` で取れます。

| キー | 値 | 意味 |
|---|---|---|
| `state` | true / false | この集計を使う。false の行は保存されるが実行されない |
| `name` | 文字 | 処理名（覚え書き。レコード画面には出ない） |
| `app` | `{ id, fcode }` | 対象アプリ。下の「対象アプリの決め方」 |
| `orFrom` | null か 2 以上の番号 | OR 条件の位置。下の「対象アプリ条件」 |
| `filters` | 並び | 対象アプリ条件 |
| `order` | 並び | 集計順 |
| `fields` | 並び | 集計項目 |
| `table` | オブジェクト | テーブル項目 |
| `reflect` | オブジェクト | 反映 |

### 対象アプリの決め方（`app`）

- `fcode`: 自アプリの**ルックアップ**か**関連レコード一覧**の項目コード。その項目の参照先が対象アプリになります。別の環境へ設定を移しても、項目から参照先を引き直すので、こちらを勧めます。
- `id`: 対象アプリの番号。`fcode` を書かないとき（参照する項目が無いアプリを集計するとき）に書きます。
- 両方を書いたときは `fcode` が優先です。設定画面でダウンロードしたファイルから作った設定ファイルには、`fcode` と一緒に `id`（そのときの対象アプリの番号）も入っています。
- `fcode` から参照先を引けないとき（その項目がルックアップ・関連レコード一覧でない、参照先のアプリの名前を読めない）は、`id` があれば `id` のアプリを使い、warning（`app.fcodeFallback`）で伝えます。このとき保存値に `fcode` は入りません（設定画面と同じ動き）。別の環境へ移した設定でこれが出たら、同じ番号の別のアプリを指していないかを利用者に確かめます。`id` も無ければ error（`app.fcode`）です。
- 検査で読むのは、**行が使うアプリだけ**です（自アプリにあるほかのルックアップ・関連レコード一覧の参照先は読みません）。

### 対象アプリ条件（`filters`、`orFrom`）

対象アプリから、集計するレコードを取り出す条件です。

| キー | 値 | 意味 |
|---|---|---|
| `state` | true / false | この条件を使う |
| `field` | **対象アプリ**の項目コード | テーブル内の項目、関連レコード一覧の表示項目（`関連コード.項目コード`）も書ける。添付ファイル・リンク・グループ・カテゴリーは書けない |
| `cond` | 下の表 | 項目のタイプで決まる |
| `value` | 式（**自アプリ**の項目） | 条件値。`in` / `not in` は配列を返す式（例 `ARRAY("A","B")`） |

`orFrom`: null なら、条件を全部 AND でつなぎます。番号 N を書くと、有効な条件の **N 番目から下を OR でつなぎます**（1 〜 N−1 番目は AND、その後ろは `( N 番目 or N+1 番目 or … )`）。

- 書けるのは **2〜10**（条件が 10 個を超えるときは、その数まで）。設定画面で選べる範囲と同じです。範囲の外は error（`filter.orFrom`）。
- OR が効くのは、**有効な条件の数が N より多いとき**だけです（OR でつなぐ条件が 2 つ以上になるとき）。有効な条件が 3 つなら、効くのは N = 2 だけ（`1 番目 and ( 2 番目 or 3 番目 )`）。N = 3 は OR でつなぐ相手が無いので、全部 AND と同じ動きになります。
- 効かない番号（N が有効な条件の数以上）は、設定画面でも保存できるので止めませんが、warning（`filter.orFromNoEffect`）で伝えます。OR にしたいなら、番号を小さくするか条件を足します。

**項目のタイプと、使える条件**

| タイプ | 使える条件 |
|---|---|
| 文字列（1行） | `=` `!=` `in` `not in` `like` `not like` |
| 数値、計算、レコード番号（`$id` も） | `=` `!=` `>` `<` `>=` `<=` `in` `not in` |
| 日付、時刻、日時、作成日時、更新日時 | `=` `!=` `>` `<` `>=` `<=` |
| 文字列（複数行）、リッチエディター | `like` `not like` |
| チェックボックス、ラジオボタン、ドロップダウン、複数選択 | `in` `not in` |
| ユーザー選択、組織選択、グループ選択、作成者、更新者 | `in` `not in` |
| ステータス | `=` `!=` `in` `not in` |
| 関連レコード一覧の表示項目 | `in` `not in` |

**テーブル内の項目は `=` と `!=` を使えません。** `in` / `not in` を使います（kintone の検索の決まり）。

日付・日時の項目では、条件値を日付・日時の書式に直してから比べます。

**条件値が空のとき**: 条件は外れません。空の値と比べます（条件値の項目が空なら `製品番号 = ""` になり、製品番号が空のレコードだけが当たります）。

### 集計順（`order`）

取り出したレコードを集計する順番です。`first` / `last` の結果と、テーブルに出す行の順番が決まります。

| キー | 値 |
|---|---|
| `state` | true / false |
| `field` | **対象アプリ**の、テーブルの外の項目コード。日付・時刻・日時・文字列（1行）・数値・レコード番号・`$id`・作成日時・更新日時・計算・ステータス・リンク |
| `order` | `asc`（昇順）/ `desc`（降順） |

### 集計項目（`fields`）

自アプリの項目に、対象アプリのレコードを集計した値を入れます。

| キー | 値 | 意味 |
|---|---|---|
| `state` | true / false | |
| `to` | **自アプリ**の、テーブルの外の項目コード | 値を入れる項目（集計先）。日付・時刻・日時・文字列（1行）・数値・チェックボックス・ラジオボタン・ドロップダウン・複数選択・ユーザー選択・文字列（複数行）・グループ選択・組織選択・リンク |
| `summary` | 下の表 | 集計の種類 |
| `formula` | 式（**対象アプリ**の項目。自アプリは `#項目コード`） | 対象アプリのレコード 1 件ごとに評価する |
| `init` | true / false | 集計の前に入れる値。true は 0、false は空。下の「集計の前の初期化」 |
| `editable` | true / false | true なら、集計先の項目を画面で編集できる（false は編集不可） |

同じ `to` を 2 回書くと、検査が止めます。

**集計の前の初期化**: 集計のたびに、集計先の項目をいったん初期化してから集計した値を入れます。前の集計の値は残りません。

- `init` が false: 空にする（対象のレコードが無ければ、空のまま）
- `init` が true: 0 を入れる（対象のレコードが無ければ 0 になる）。**項目のタイプに関わらず 0 が入る**（文字列の項目には「0」が入る）
- チェックボックス・複数選択・ユーザー選択・組織選択・グループ選択は、`init` に関わらず「選択なし」にする
- テーブル項目を使う行では、出力先のテーブルを空にしてから行を出す

**集計の種類（`summary`）**

| 値 | 意味 |
|---|---|
| `sum` | 合計 |
| `min` / `max` | 最小 / 最大 |
| `count` | 件数 |
| `c_uniq` | 重複を除いた件数 |
| `first` / `last` | 先頭 / 最後のレコードの値（集計順で決まる） |
| `firsta` / `lasta` | 空でない最初 / 最後の値 |

### テーブル項目（`table`）

自アプリのテーブルに、対象アプリのレコード（またはそのテーブルの行）を行として出します。集計キーでまとめることもできます。

| キー | 値 | 意味 |
|---|---|---|
| `enabled` | true / false | テーブルへの出力を使う |
| `to` | **自アプリ**のテーブルのコード | 出力するテーブル |
| `from` | **対象アプリ**のテーブルのコードか `""` | 書くと、そのテーブルの行ごとに出力する |
| `delrowDisabled` | true / false | プラグインが出した行を、画面で削除できないようにする |
| `hideRecid` | true / false | 識別ID の項目を画面に出さない |
| `totalling` | true / false | 集計キーが同じ行をまとめて 1 行にする |
| `loop` | `{ state, formula }` | ループ配列。式が返した配列の数だけ、レコード 1 件から行を作る（値は `$val`）。既定は `ARRAY(0)` |
| `out` | `{ state, formula }` | 出力条件。式が偽の行は出さない。既定は `1` |
| `items` | 並び | 出力する項目。**書かなかった項目は「選択なし」になる**（検査が、自アプリのテーブルの項目を全部並べ直す） |

`items` の要素:

| キー | 値 | 意味 |
|---|---|---|
| `state` | true / false | この項目に出力する |
| `to` | `table.to` のテーブルの中の項目コード | |
| `formula` | 式（**対象アプリ**の項目。自アプリは `#項目コード`） | `state` が true なら必須 |
| `recid` | true / false | 識別ID。対象アプリのレコード番号を控える項目。**1 つだけ**。文字列（1行）か数値の項目。式は `$id` になる（`formula` は書かないか `$id`）。反映を使うときに必要 |
| `edit` | true / false | true なら、出した行のその項目を画面で編集できる |
| `sumkey` | `""` か 1〜10 | 集計キー。番号の順にまとめる（`totalling` が true のとき） |
| `order` | `""` / `asc` / `desc` | 集計キーの並び。`sumkey` を書いて省略すると `asc` |
| `summary` | `""` か集計の種類 | まとめた行の集計の種類。**集計キーの行には書けない** |
| `sortkey` | `""` か 1〜10 | ソートキー。まとめた後の行の並び |
| `sortOrder` | `""` / `asc` / `desc` | `sortkey` を書いて省略すると `asc` |

決まり:

- `totalling` が true なら、`sumkey` を持つ有効な項目が 1 つ以上要ります。
- 識別ID の行には、`sumkey` と `summary` を書けません。
- `order` / `sortOrder` は、キー（`sumkey` / `sortkey`）を書いた行にだけ書きます。

**識別ID に入る値**: `アプリ番号:レコード番号`（例 `1353:12`）です。集計キーでまとめた行には、まとめたレコードの分がカンマ区切りで入ります（例 `1353:12,1353:15`）。数字だけの値ではないので、識別ID には文字列（1行）の項目を勧めます。

**集計キーの値が空のレコード**: 空の値どうしで 1 行にまとまります（その行の集計キーの項目は空のまま）。

**対象のレコードが 0 件のとき**: テーブルは空になります（編集画面では、kintone が空の 1 行を表示します）。

**出力先のテーブルにルックアップの項目があるとき**: そのルックアップの項目に値を入れる行が `items` に無ければ、出した行のルックアップは空になります（取得していない状態）。

### 反映（`reflect`）

集計した後に、**対象アプリのレコードの項目を更新します**（対象アプリのレコードが書き換わります）。使うには、テーブル項目で識別ID を決めておきます（無いと、検査が warning を出します）。

更新するのは、テーブルに出した行の識別ID にあるレコードです。集計キーでまとめた行は、まとめたレコードを**全部**更新します。入れる値は、行ごとに式を評価したものです。

| キー | 値 | 意味 |
|---|---|---|
| `cond` | `{ state, formula }` | 更新時反映条件。レコードの保存のときに、式（**自アプリ**の項目）が真なら反映する。既定は `1` |
| `items[].state` | true / false | |
| `items[].to` | **対象アプリ**の、テーブルの外の項目コード | 更新する項目。日付・時刻・日時・文字列（1行）・数値・チェックボックス・ラジオボタン・ドロップダウン・複数選択・ユーザー選択・リンク |
| `items[].formula` | 式（**自アプリ**の項目） | 入れる値。テーブル項目に出した行の項目も使える |

## 行の外の設定（`common`）

```json
{
  "pluginEnable": true,
  "pluginComment": "",
  "pluginDescription": "",
  "btnInfo": { "create_show": { "state": false, "default": "…", "ja": "", "en": "", "zh": "" }, … },
  "listInfo": { "all_enabled": true, "views": {} },
  "authority": { "everyone": true, "users": {}, "organizations": {}, "groups": {} },
  "executeCondition": { "state": true, "enabled": true, "formula": "1" }
}
```

| キー | 意味 |
|---|---|
| `pluginEnable` | プラグインを有効にする |
| `pluginComment` | NOTE（設定の覚え書き） |
| `pluginDescription` | 説明 |
| `btnInfo` | 自動・ボタン別設定。下の表。各キーは `{ state, default, ja, en, zh }`（`state` = 使う、`ja` / `en` / `zh` = ボタンの名称〈言語別。空なら `default`〉） |
| `listInfo` | 一覧別設定。`all_enabled` が true なら、すべての一覧に一括集計のボタンを出す。false のときは `views` に `{ "一覧の ID": "一覧の名前" }` を書いた一覧だけ |
| `authority` | 権限設定。`everyone` が true なら全員にボタンを出す。false のときは `users` / `organizations` / `groups` に `{ "コード": "名前" }` を書いた利用者だけ |
| `executeCondition` | 実行条件。`enabled` が true のとき、`formula`（**自アプリ**の項目）が偽なら、追加・編集画面のボタンを隠し、保存時の自動集計もしない（プラグイン全体で 1 つ） |

**`btnInfo` のキー**

| キー | 意味 |
|---|---|
| `create_show` | レコードの追加画面を開いたときに集計する |
| `edit_show` | 追加画面と編集画面を開いたときに集計する |
| `edit_auto` | 追加・編集の画面で、対象アプリ条件の条件値や反映に使う項目が変わったら集計する |
| `edit_save` | 追加・編集の保存のときに集計する |
| `edit_btn` | 追加・編集の画面に集計のボタンを出す（名称を付けられる） |
| `list_btn` | 一覧画面に一括集計のボタンを出す（名称を付けられる） |
| `list_formula` | 一括集計のときに、計算式プラグインの計算も行う |

一覧の ID、利用者・組織・グループのコードは**推測しません**。利用者に聞くか、今の設定（設定画面でダウンロードしたファイルから作った設定ファイル）の値を使います。

## 検査の指摘

`agg_check` と `agg_export` は、指摘を `{ severity, code, rowKey, section, label, message }` で返します。

- `error`: 直すまで、取り込み用のファイルを作れません。
- `warning`: 作れますが、利用者に伝えます。
- `rowKey`: 行のキー。行の外の設定は `common`。
- 無効な行（`state` が false）の誤りは、`disabled.` で始まる `code` の warning になります。**無効な行の中身は、誤りがあってもそのまま持ち続けます**（項目の有効・無効も変えません）。行を有効に戻すと、同じ誤りが error になって止まります。
  - 対象アプリが決まらない・読めない無効な行（`disabled.app.unknown` / `disabled.app.noFields` / `disabled.app.fcode`）は、条件・集計順・反映を項目コードのまま持ち続け、式は検査しません（指摘はその 1 件だけ）。
  - テーブル項目だけは、いまの自アプリのテーブルの項目から並べ直します（設定画面と同じ）。いまの項目定義に無い項目は保存値に入りません（有効な項目なら error、無効な項目なら warning の `field.notInTable`）。

| code | 意味 |
|---|---|
| `app.fcode` / `app.unknown` / `app.noFields` | 対象アプリが決まらない（項目コードが参照の項目でない、アプリが見つからない・読めない） |
| `app.fcodeFallback`（warning） | `fcode` から参照先を引けないので、`id` のアプリを使った（保存値に `fcode` は入らない） |
| `field.notInTarget` / `field.notInOwn` / `field.notInTable` | 項目が、そのアプリ（テーブル）に無い。自アプリと対象アプリの取り違えもここに出る |
| `field.inTable` / `field.type` | テーブル内の項目は選べない場所、選べないタイプ |
| `field.duplicate` | 同じ項目を 2 回書いた |
| `cond.notAllowed` | その項目のタイプで使えない条件 |
| `filter.orFrom` | OR 条件の位置が範囲の外（2〜10。条件が 10 個を超えるときはその数まで） |
| `filter.orFromNoEffect`（warning） | OR 条件の位置が有効な条件の数以上で、OR でつなぐ条件が無い（全部 AND と同じ動き） |
| `order.value` / `summary.value` | `asc` / `desc`、集計の種類でない値 |
| `formula` | 式の誤り（文法、項目が無い、取り違え、必須なのに空） |
| `execCond.formula` | 実行条件の式の誤り |
| `table.to` / `table.from` | テーブルが無い |
