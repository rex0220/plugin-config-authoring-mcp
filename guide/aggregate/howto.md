# アプリ集計: 作業手順

アプリ集計プラグインの設定を、要件から作る・今の設定を直すときの手順です。ツールは `agg_*`。**kintone には何も書きません。** 作るのは作業フォルダーのファイルで、設定画面への読み込みと保存は利用者が行います。

## 始める前に

1. `agg_status` で、プラグインの zip と kintone の接続が読めるかを確かめる。`problem` や `not-configured` があれば、利用者に設定を頼む（zip の場所、接続のファイル）。自分で直そうとしない。
2. 作る前に、利用者の頼みがアプリ集計に向いているかを確かめる。
   - **向いている**: ほかのアプリのレコードを条件で取り出し、合計・件数・最初や最後の値を、このアプリの項目やテーブルに入れる。
   - **向いていない**: 1 つのレコードの中だけの計算（計算式プラグイン）、入力の検査（項目検証プラグイン）、複数のアプリをまたぐ更新の手続き。向いていなければ、作る前にそう伝える。

## 新しく作る

1. **項目を確かめる**。`agg_fields` で、自アプリ（`preview: true`）と対象アプリの項目コード・タイプ・テーブルを読む。項目コードは推測しない。自アプリのルックアップ・関連レコード一覧が対象アプリを指していれば、その項目コードを `app.fcode` に使う。
2. **設定ファイルを作る**。`agg_new`（`file` と `app` = 自アプリの番号）。
3. **行を足す**。`agg_read` の `key: "new"` で行の雛形を取り、中身を入れて `agg_update` の `addRow` で足す。書き方は `agg_docs` の `spec`。式を書く場所ごとに、使える項目のアプリが違う（`spec` の表）。
4. **検査する**。`agg_check`。`error` を直して、もう一度検査する。指摘はそのまま利用者に伝える。
5. **取り込み用のファイルを作る**。`agg_export`（`expectedDigest` は `agg_check` が返した設定ファイルの digest）。返った `nextSteps` を利用者に伝える。

## 今の設定を直す

1. 利用者に、設定画面の「設定をダウンロード」で今の設定をファイルに出して、作業フォルダーの直下に置いてもらう。
2. `agg_files` でそのファイルを確かめ、`agg_new` の `from` に渡して設定ファイルにする（元のファイルは残る）。
3. `agg_read` で要約と行を読み、直す所を利用者と確かめてから `agg_update` で直す。行の一部だけを直すなら `patchRow`、並びの中の 1 つを直すなら、行を読んで直して `setRow`。
4. `agg_diff` で、直す前の設定ファイルとの差を確かめる（直す前のものを別の名前で `agg_new` の `from` から作っておくと比べられる）。
5. `agg_check` → `agg_export`。

## 直すときの決まり

- `agg_update` は、`agg_read` で読んだ digest を `expectedDigest` に渡す。`conflict` が返ったら、読み直してからやり直す。ほかのツールでファイルを書き換えない。
- 行を足す・消す・動かすと、行のキーは位置で振り直る。続けて直すときは、返った `rows` のキーを使う。
- 一覧の ID、利用者・組織・グループのコードは推測しない。今の設定の値を使うか、利用者に聞く。
- 使わなくなった行は、消すか `state: false` にする。どちらにするかは利用者に聞く。

## 最後に必ず伝えること

- kintone には何も書いていない。反映は、設定画面で「設定をアップロード」→「設定」→「保存する」（運用環境に反映）。取り込むと、今の設定はファイルの内容に全部入れ替わる。
- 保存しただけでは既存のレコードは変わらない。集計は、ボタンか、画面表示・項目の変更・保存のときの自動集計で行われる。
- 式は架空のレコードで検査しただけ。保存の後、レコードを 1 件開いて集計し、値を確かめる。
- 「反映」を使う設定は、集計のときに対象アプリのレコードを書き換える。
- warning の指摘があれば、消さずに伝える。
